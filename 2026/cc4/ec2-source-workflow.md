# 公開リポジトリがない環境でのEC2調査とソース取得

大会当日に公開リポジトリがなくても、SSHでEC2の稼働構成を調べ、必要なソースを開発VMへ取得して検索・編集できる。本手順は初回の調査・読解用であり、完全バックアップや配備手順ではない。当日マニュアルと許可範囲を優先する。

## 1. 接続と構成を確認する

SSH設定・ホスト鍵を用意し、非対話でユーザー・ホストを確認する。Codexで共通設定の所有者エラーが出る場合の `-F` 指定は [README](./README.md) を参照する。

```bash
ssh -F /PATH/TO/SSH_CONFIG -o BatchMode=yes -o StrictHostKeyChecking=yes \
  -o ConnectTimeout=10 SSH_HOST 'id; hostname; pwd'
```

systemdのUser・WorkingDirectory・ExecStartから、実行ユーザー、ソースの場所、起動方法を特定する。待受ポート、Nginx等のリクエスト経路、DB、定期処理、CPU・メモリ・ディスク、アプリ配下の容量も調べる。複数台の場合は役割を区別する。起動設定や環境変数には秘密情報があり得るため、必要な項目だけを記録する。

## 2. 既存cloneとは別の保存先を用意する

既存cloneの外に、対象と取得日時を区別できるディレクトリを作る。Codexが書き込める永続保存先を事前に用意する。

```text
SNAPSHOT_DIR/
  webapp/       選別したソース
  inspection/   稼働構成、DB構造、ファイル一覧、照合結果
  README.md     取得条件、構成、未確認事項
```

`/tmp` は練習の一時保存には使えるが、清掃や再起動で失われ得る。取得物は本戦の非公開情報として扱い、公開TIPSへコピーしない。

## 3. 大きなデータと秘密情報を除外する

最初は稼働言語のソース、依存関係定義・ロックファイル、API仕様、スキーマ、初期化スクリプトを選ぶ。設定は必要なファイルを個別に取得する。

依存ライブラリ（node_modules、vendor、.venv等）、ビルド成果物、DB本体、データダンプ、大量ログ、環境ファイル、秘密鍵は原則除外する。拡張子だけでは秘密情報やデータダンプを判別できないため、対象一覧を確認する。

VMとEC2にrsyncがあれば、除外規則とファイルサイズ上限を指定して取得できる。最初は `--dry-run --itemize-changes` で確認する。読み取りにsudoが必要なら、所有ユーザーに合わせた `--rsync-path` を使う。SSH設定は `-e` で指定する。

rsyncは最初に一致した規則を適用するので、除外規則を許可規則より先に置く。サイズ上限で重要ソースを落とさないよう、除外したファイルも確認する。シンボリックリンクや実行権限の保存が必要なら、取得オプションを別途設計する。

## 4. DBとログは要約から調べる

DBは全件ダンプせず、スキーマ、インデックス、容量、推定行数を先に確認する。MySQLのinformation_schema.TABLESのTABLE_ROWSは推定値であり、正確な件数ではない。構造の記録は復元用バックアップにはならない。

ログは期間・サービス・行数を限定する。必要な短い抜粋や集計だけを保護された場所に保存する。認証情報や個人情報を公開記録へ含めない。

## 5. 取得内容を照合して記録する

取得ファイルの一覧とSHA256を保存し、EC2側の対応ファイルと照合する。取得中は編集・配備を避ける。照合はファイル内容の一致を確認するもので、稼働バイナリとソースの一致や、全ファイルが同時点の状態であることまでは保証しない。

スナップショットのREADMEには次を残す。

- 取得日時・対象・ソースの場所・保存先
- サービスの実行ユーザー・起動方法・リクエスト経路・DB・定期処理
- 取得対象・除外対象・容量制限・照合結果・再取得方法
- 初期化・ベンチ・配備方法と、それぞれの確認状況
- 未取得データ・未確認事項・完全復元に必要なもの

取得後は秘密情報を点検し、ローカルGitで初期状態を保存できる。データ・バイナリ・依存関係を除外した読解用コピーだけでは、完全な実行や復元はできない。
