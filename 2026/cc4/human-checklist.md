作成日: 2026-10-07 JST。cc4の事前の運用想定。担当・期限・実施記録は本戦用の非公開領域へ複製して記入し、この公開ファイルに実環境のIP・鍵・クーポンコード・当日情報を追記しない。チェックが付いていない項目は未実施を意味するテンプレートであり、現在の状態を示していない。

- [ ] 人間の担当を決める: AWS・接続の準備、公開制限、Discord・ポータル監視、障害復旧。それぞれ主担当と代替担当を決め、変更はチーム内へ伝える。
- [ ] 最新の参加規約・レギュレーション・事前準備・Discord告知を確認し、必要な期限を記録する。
- [ ] 全選手のDiscord参加・通知を確認する。原則、全体アナウンスはDiscord、競技中の質問・サポートはポータル。両方へログインできる状態にする。[公式規定](https://isucon.net/archives/59966826.html)
- [ ] AWSの対象アカウント・リージョン、IAM権限、ログイン・MFA、利用上限、予算、復旧経路を確認する。サーバーを起動する権限と、OS内で操作する権限を区別する。
- [ ] AWSクーポンが今年配布される場合は、案内の対象アカウント・期限・適用条件に従い、適用と残額を確認する。今年の配布を前提にしない。コードは公開記録に入れない。
- [ ] Linux VMの起動・スリープ防止・ネットワーク・空き容量・時刻同期・遠隔接続・認証を確認する。必要なツール、永続保存先、Codexからのファイル操作・SSHを練習する。
- [ ] 競技用の鍵・Agentと人間の復旧用鍵を準備する。公開鍵と秘密鍵を区別し、秘密鍵をチャット・Git・EC2へコピーしない。
- [ ] 本戦用の非公開リポジトリと作業領域を用意し、アクセスを自チームに限定する。公開TIPSから分離し、復元可能な記録方法を練習する。
- [ ] 公開する必要のあるTIPS更新を事前に終え、当日用資料をVMのローカルへ保存する。連携の対象から外した後も資料を参照できるようにする。

## 大会前・開始直前: Codexの利用枠と復旧手段を確認する

- [ ] 使用量監視の主担当・代替担当と確認間隔を決める。競技開始前、定期確認、消費が増えた時、終了前の検証に入る前に残量を確認する。
- [ ] 使用量画面で短期枠・週間枠等の残量と自然回復時刻を確認し、JSTで非公開記録へ残す。アカウント全体の利用枠なので、他のチャット・利用も含む。プランによって表示・枠は異なり、取得できない値をゼロと解釈しない。
- [ ] この練習ではCodexから読み取り用ツールで使用量を取得できた。当日も取得可能か確認し、プロンプトでの確認を補助に使う。上限でエージェントが動けなくなる可能性があるため、人間が画面から確認する経路も用意する。[公式の使用量・クレジット案内](https://learn.chatgpt.com/docs/pricing)
- [ ] 使用量リセットが付与されている場合は、残り回数・有効期限・対象枠・利用条件を確認する。以前の練習で残っていた回数や期限が大会日も同じとは仮定しない。
- [ ] 追加クレジット・課金が必要になる場合の予算上限、購入担当、支払い・管理者権限、購入画面へのアクセスを確認する。購入可否・価格・適用範囲はプランと当日の画面で確認する。API課金とサブスクリプションの利用枠を混同しない。
- [ ] 残量が少なくなった時の判断を決める: 自然回復を待つ、リセットを使う、追加購入する、作業範囲・モデルを見直す、人間が復旧・最終確認を行う。停止前に非公開STATUS.mdと正常版・復元方法が残る運用にする。

この環境のリセット実行ツールは、対象の5時間枠または週間枠の残量が10%以下の場合に、1回ごとの明示的な人間の承認を必要とする。当日は利用可能な機能と最新条件を再確認する。このチェックリストや監視依頼は、リセット・購入の包括的な承認ではない。自動でリセットや購入を行わない。

## 競技前: 公開先へのアクセスを制限する

この操作は組織のGitHub App設定を扱うため人間が実施する。今回の文書追記は、設定変更そのものの実施ではない。

- [ ] ChallengeClubにインストールされた、CodexのGitHub連携に使うAppを特定する。変更前の対象リポジトリと復元方法を控える。
- [ ] 設定が他の参加メンバーへ与える影響を事前に確認し、変更時刻・担当・戻す時期を合意する。
- [ ] Appのリポジトリアクセスを選択対象に限定し、公開isucon_tipsを対象から外す。本戦用の非公開リポジトリだけを必要な範囲で許可する。「全リポジトリ」設定になっていないか確認する。[GitHub公式手順](https://docs.github.com/en/apps/using-github-apps/reviewing-and-modifying-installed-github-apps)
- [ ] Codex側で対象外になったことを読み取り・アクセス確認で検証し、本戦用非公開リポジトリには必要なアクセスが残ることを確認する。公開先へのテスト投稿・テストpushはしない。
- [ ] 別のGitHub App、PAT、gh CLI、GitのHTTPS資格情報、SSH鍵、別アカウント等による公開先への書き込み経路が残っていないか確認し、競技用環境では使えないようにする。Appの対象から外すだけでは、独立した認証経路までは制限されない。
- [ ] 自動push、公開Actions・CI、ログ転送、チャット共有等を点検する。非公開リポジトリでも参加者以外が読める設定になっていないか確認する。
- [ ] 制限完了を本戦用の非公開STATUS.mdに記録し、Codexへ「競技中の公開先更新禁止」を伝える。利用可能な権限を公開許可とは扱わない。

## 競技開始後: マニュアルから環境を立ち上げる

- [ ] 指定されたAMIと起動手順を確認する。リージョン・台数・インスタンスタイプ・ディスク・ネットワーク・タグ等を当日指定に合わせる。過去問設定をそのまま流用しない。
- [ ] EC2の起動・準備完了を確認し、対象インスタンスの識別情報を非公開記録へ保存する。
- [ ] 初回接続用ユーザーと認証方法を確認する。必要な場合は、ubuntu等の指定ユーザーのauthorized_keysへ競技用公開鍵を追加する。既存鍵・運営用アクセスを削除せず、所有者・権限を確認して別セッションで接続を検証する。
- [ ] 日時・時刻同期・タイムゾーンを確認する。OSをAsia/Tokyoへ変更する場合は当日制約とアプリ・DBへの影響を確認する。UTCで正常な環境を必ず変更する必要はなく、ログの表記と非公開記録の時刻を揃える方法も選べる。
- [ ] Linux VMの.ssh/configへ、指定ユーザー・鍵・最新の接続先を設定する。IPv6は許可構成とVMからの到達性を確認した場合に使う。自動割当IPv4は停止・起動時に変わり得るため、起動後に最新値を確認する。
- [ ] 信頼できる経路で接続先のホスト鍵を照合し、known_hostsへ登録する。ssh-keyscanの取得だけを本人確認とせず、StrictHostKeyCheckingを無効にして解決しない。
- [ ] 人間の通常端末とCodexの実行環境の両方で、非対話SSH・必要なsudo・小さなファイル転送を確認する。共通設定の所有者エラーにはREADMEの-F手順を使う。
- [ ] ホストごとの役割、実行ユーザー、サービス、DB、初期化とベンチの方法をCodexへ渡す。公開cloneの代わりにEC2から取得する場合は[取得手順](./ec2-source-workflow.md)を使う。
- [ ] 本戦の非公開STATUS.mdに接続・権限・復旧の確認状況と未確認項目を残す。AWS資格情報や秘密鍵そのものを渡す記録にはしない。

## 終了後: 追試と公開・撤去を分ける

- [ ] 当日マニュアルと運営案内に従い、追試に必要なEC2・データ・アクセスを維持する。終了時刻だけで停止・削除しない。
