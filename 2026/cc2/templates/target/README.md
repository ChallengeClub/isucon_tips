## 構成

- `webapp/`：回収した複数言語のソース。稼働するbackend言語は初期想定ではGoですが、serviceで確認します。
- `infra/`：回収した設定。
- `db/`：schemaなどのDB資材。
- `docs/`：対象環境の記録と操作手順。
- `scripts/`・`ansible/`：対象別に実装・検証してから追加する共通操作。

## 操作手順

- [保留・再開メモ](docs/RESUME.md)：mainと実機の差・保留候補・復旧元。
- [視点転換のタネ](docs/STRATEGY-SEEDS.md)：未検証案を一旦置き、頭打ち時に見返す。

[対象別RUNBOOK](docs/RUNBOOK.md)へ接続先・配置・稼働言語・ビルド・復旧方法を記入します。
このリポジトリだけでも手順を読めるよう、実行に必要な情報は外部のチーム資料だけへ依存させません。
チーム資料は任意の補足参照先として記録します。

認証ファイル・生ログ・大容量データはGitへ登録しません。例外的な対象の操作を確認せず他問題へ流用しないでください。
