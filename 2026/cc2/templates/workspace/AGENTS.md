# repositoryと作業前確認

- workspaceのルート自体はGitリポジトリではありません。
- ファイル変更前に所属repositoryを確認し、対象repository・現在のbranch・Git statusを提示してください。Git管理外なら、その旨を示してください。
- workspace全体に対する `git add .` は実行しないでください。
- `references/` は読み取り専用です。`artifacts/` の結果・ログをコミットしてはいけません。

# 承認とリモート操作

- commit・push・merge・deploy・benchmark実行は、明示的な承認を得てから行ってください。
- 許可された接続先に対する読み取り専用の調査は行えます。
- リモートのファイル・設定・権限・service・パッケージ・DBを変更する操作には、明示的な承認が必要です。
- 接続先は、使用前に以下へ実際のSSHエイリアスを記入してください。未記入の接続先へは接続しないでください。任意のIPや別ホストへ接続しないでください。

| 役割 | 許可するSSHエイリアス |
|---|---|
| 対象サーバー | 未記入 |
| benchmarkサーバー | 未記入 |

GitHubへのアクセスはworkspaceの一部として明示されたrepositoryに限定します。このSSH接続先制限は、それらのrepositoryへのclone・fetch・pullを禁止するものではありません。

# 認証情報

秘密鍵や環境固有の認証値を、出力・回収・Git登録しないでください。環境全体をdumpせず、EnvironmentFileやcredentialファイルはパスと非秘密metadataのみ確認してください。
公開upstreamと一致する教材用の固定値は、キーワードだけで削除・環境変数化せず、出所と用途を確認して既存の動作を維持してください。
